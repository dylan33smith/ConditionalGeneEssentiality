### Assumption Under Test

The frozen ProteomeLM-L layer 8 gene embeddings used throughout T1-T4 may
be suboptimal in three different ways:
- assumption_1 (T5-A, H-EMB-02): A learnable adapter MLP between the frozen
  embedding and the fusion concat point unlocks signal the current
  architecture is missing.
- assumption_2 (T5-B, H-EMB-03): A different ProteomeLM-L layer (we currently
  use 8 of 18) provides a better representation for this task.
- assumption_3 (T5-C, H-EMB-04): ProteomeLM's proteome-context layer adds
  value over raw ESM-C 600M embeddings.

- assumption_type: representation
- why_it_matters: T2-T4 results showed sub-threshold improvements only. The
  val curves plateau early while train continues to improve, suggesting the
  bottleneck is upstream of the prediction head — likely in the gene
  representation itself.

### Pre-Registered Test Plan

All experiments share:
- split_protocol_id: `multi_org_balanced`
- feature_contract_id: `de21504134c84a6c`
- quality_policy_id: `weighted_full` + full org pool
- T1 representation (chemistry side): 425-dim binary multihot (T1-DEC-004)
- T2 fusion: early-concat (T2-DEC-001)
- T3 architecture: 2-layer ResidualMLP, hidden_dim=512 (T3-DEC-001)
- T4 locks: MSE loss, raw targets, 8 epochs constant lr=1e-3 (T4-DEC-001, T4-DEC-002)
- seeds: {0, 1, 2}
- S2-locked thresholds: RMSE=0.0212, MAE=0.005

#### T5-A (H-EMB-02): Learnable Gene Adapter
Adds an MLP after frozen gene embedding, before concat:
- no_adapter:        identity (T3 baseline)
- adapter_256:       Linear(1152, 256) → ReLU → Dropout → Linear(256, 1152)
- adapter_512:       Linear(1152, 512) → ReLU → Dropout → Linear(512, 1152)
- adapter_1024_proj: Linear(1152, 1024) → ReLU → Dropout → Linear(1024, 512)
  (also reduces gene dim 1152 → 512 before concat)

#### T5-B (H-EMB-03): Layer Ablation
Re-encoded all 48 organisms with ProteomeLM-L at multiple layers, swapping
the gene embedding input only (architecture identical):
- layer_0:  input embedding (after ESM-C projection, before any PLM block)
- layer_4:  early ProteomeLM representation
- layer_8:  current locked choice
- layer_12: late-middle representation
- layer_18: final ProteomeLM layer

#### T5-C (H-EMB-04): ProteomeLM Bypass
Encoded all 48 organisms with raw mean-pooled ESM-C 600M (1152-dim, same
shape as PLM layer 8), bypassing ProteomeLM entirely:
- plm_layer8: current locked choice (control)
- esmc_only:  raw ESM-C, no proteome-context pass

### Evidence Summary

#### T5-A (H-EMB-02)

| Arm | RMSE (mean ± std) | MAE (mean ± std) |
|---|---:|---:|
| no_adapter | 0.5034 ± 0.0007 | 0.2805 ± 0.0008 |
| adapter_256 | 0.5031 ± 0.0006 | 0.2799 ± 0.0003 |
| adapter_512 | 0.5015 ± 0.0011 | 0.2803 ± 0.0004 |
| **adapter_1024_proj** | **0.4991 ± 0.0011** | **0.2780 ± 0.0008** |

adapter_1024_proj wins on both co-primary metrics with disjoint bootstrap
CIs vs every other arm. RMSE gap 0.0043 vs no_adapter (20% of threshold),
MAE gap 0.0025 (50% of threshold). Improvement is real and consistent
across all 3 seeds. The dimension-reduction variant (1152 → 512) is what
unlocked the gain — the same-dim adapters (256, 512) showed minimal effect.

#### T5-B (H-EMB-03)

| Arm | RMSE (mean ± std) | MAE (mean ± std) |
|---|---:|---:|
| layer_0 | 0.5027 ± 0.0016 | 0.2831 ± 0.0014 |
| layer_4 | 0.5033 ± 0.0033 | 0.2811 ± 0.0018 |
| **layer_8** | **0.5028 ± 0.0003** | **0.2799 ± 0.0007** |
| layer_12 | 0.5134 ± 0.0021 | 0.2847 ± 0.0004 |
| layer_18 | 0.5599 ± 0.0011 | 0.3007 ± 0.0013 |

Layer 8 is essentially tied with layers 0 and 4 on RMSE but wins on MAE.
Layers 12 and 18 are dramatically worse (RMSE 0.51 → 0.56). The final
layers are over-specialized for ProteomeLM's masked-LM objective and lose
generalization. The existing layer-8 choice is well-justified —
**no change to the PLM layer.**

#### T5-C (H-EMB-04)

| Arm | RMSE (mean ± std) | MAE (mean ± std) |
|---|---:|---:|
| **plm_layer8** | **0.5030 ± 0.0001** | **0.2801 ± 0.0006** |
| esmc_only | 0.5090 ± 0.0008 | 0.2844 ± 0.0004 |

ProteomeLM-L layer 8 beats raw ESM-C by RMSE 0.0060 (28% of threshold)
and MAE 0.0043 (86% of threshold). Bootstrap CIs disjoint. The proteome-
context layer is providing real value over raw per-protein embeddings.
**Keep ProteomeLM-L; do not bypass.**

### Decision

- decision_outcome: **Promote T5-A adapter_1024_proj.**
  New architecture: cat([Adapter(gene[1152]) → 512], chem[425]) →
  Linear(937, 512) → ReLU → Dropout(0.1) → ResBlock(512) → Linear(512, 1).
  Adapter: Linear(1152, 1024) → ReLU → Dropout(0.1) → Linear(1024, 512).

- rationale:
  1. T5-A adapter_1024_proj is the first meaningful, statistically robust
     improvement over T3 baseline in the entire T2-T5 sweep (RMSE -0.0043,
     MAE -0.0025, disjoint bootstrap CIs).
  2. The dimension reduction (1152 → 512) is what helped, suggesting the
     frozen embedding contains redundant/noisy dimensions for this task.
     The model performs better when the gene representation is compressed
     to a learned subspace.
  3. T5-B confirms layer 8 was a good choice — no need to switch layers.
  4. T5-C confirms ProteomeLM is adding value over raw ESM-C — no need
     to bypass.
  5. T5-D (fine-tuning ProteomeLM) is deferred. The adapter result shows
     downstream-learnable processing of the embedding helps; fine-tuning
     would be the more aggressive version of the same intervention.

- risks_remaining:
  1. The RMSE/MAE gain is still sub-threshold under the strict S2 bars.
     This is a directional win, not a paradigm shift.
  2. Adapter adds ~1.4M params (1.07M → 2.45M). T4-C suggests we're not
     training-time-limited, but the larger model may benefit from longer
     training with a schedule.
  3. T5-D fine-tuning of top N ProteomeLM layers is the natural next step.
     The adapter found 0.0043 RMSE in a frozen-embedding-with-extra-head
     setup; fine-tuning could find more by adapting the embedding itself.

- next_action:
  1. Emit `data_contract/architecture_winner_v2.yaml` (supersedes T3-DEC-001
     architecture lock).
  2. T5-D (fine-tune top N ProteomeLM layers) — proceed.
  3. Consider re-running T4-C hyperparameter sweep on the new (larger)
     architecture if T5-D adds further capacity.
