### Assumption Under Test
- assumption_statement: The proposed representation_mode_mapping.yaml (with 4 modes:
  physical | mix | extract | in_silico) sensibly buckets the 5 distinct
  Decomposition_type values from v4 such that the H-ENC-05 hypothesis (decomposition-
  induced over-coupling) can be tested in T1.
- assumption_type: data
- why_it_matters: if the bucketing is wrong, T1-E (decomposition-mode indicator
  features) cannot detect the over-coupling effect, and the LB-risk policy in the
  feature contract is unsupported.

### Pre-Registered Test Plan
- comparison: examine 5–10 sample compounds per Decomposition_type bucket from v4
  Media_Components_ML (Include_in_ml=True only) and verify the assigned mode is
  semantically correct.
- success criteria:
  - direct → physical: contains directly-added defined compounds (no decomposition)
  - salt → physical: contains defined inorganic salts/ions
  - mix → mix: contains components of pre-formulated defined mixtures
  - extract → extract: contains components inferred from biological extracts
  - unrecoverable → in_silico: placeholder for media without recoverable composition
  - row counts per bucket are non-pathological (no bucket is suspiciously empty
    or 95%+ of all rows)

### Evidence Summary
Decomposition_type distribution in v4 (Include_in_ml=True, 4252 rows total):

| Decomposition_type | Row count | Sample compounds | Verdict |
|---|---:|---|---|
| mix | 1,499 | 4-Aminobenzoate (Wolfe's vitamin mix), Aluminum cation (Wolfe's mineral mix), Borate anion (Wolfe's mineral mix) | mode `mix` ✓ |
| salt | 1,392 | Chloride anion, Potassium cation, Sodium cation | mode `physical` ✓ |
| extract | 1,165 | Adenine (Yeast Extract), Adenosine (Yeast Extract), L-Alanine (Yeast Extract) | mode `extract` ✓ |
| direct | 196 | Citrate anion, Phylloquinone (Vitamin K1) | mode `physical` ✓ |
| unrecoverable | 0 | (none in v4) | mode `in_silico` (reserved, unused) |

Key findings:
- All bucket assignments are semantically correct.
- The `extract` bucket (1,165 rows) is the H-ENC-05 case: yeast-extract components
  are listed alongside the same components when added directly. The mode tag will
  let T1-E test whether explicit decomposition-source flags help the model
  distinguish "this amino acid was added as L-Alanine" from "this amino acid was
  inferred to be present because yeast extract contains L-Alanine."
- The `unrecoverable` bucket has zero rows in v4. This is consistent with v4's
  cleanup of the prior in-silico LB issue (LB is now tagged `extract` for its
  actual yeast-extract+tryptone components, not `unrecoverable`). The
  `in_silico` mode is retained in the schema for forward compatibility but
  currently produces no rows.
- No bucket pathologically dominates (largest = `mix` at 35% of rows, smallest
  non-zero = `direct` at 5%). Healthy distribution.

### Decision
- decision_outcome: **promote — representation_mode_mapping.yaml ratified as proposed.**
- rationale: empirical bucket inspection confirms the proposed mode assignments
  are semantically correct; row-count distribution is healthy; the `extract`
  bucket exists in non-trivial size, enabling meaningful H-ENC-05 testing in T1.
- risks_remaining:
  - The `in_silico` mode is currently empty. If S4 / T1 finds that no rows
    fall into this bucket, the mode flag is a 3-mode flag in practice (not 4).
    Acceptable; we keep the slot for forward compatibility (e.g., if a future
    workbook version adds in-silico components for media without recoverable
    composition).
  - The `direct` bucket is small (196 rows). Most "physical" rows actually come
    from `salt`. T1-E should report results stratified by direct vs salt to
    catch any artifact of pooling them.
- next_action:
  1. Update `data_contract/representation_mode_mapping.yaml` status from
     `proposed` to `ratified`.
  2. S4 consumes the ratified mapping when building the feature contract.
  3. T1-E uses the resulting mode tags as features for `H-ENC-05`.
